The project name, Python package name, CLI command, README, tests, examples, logs, and help messages should all use `bait2contig` from the beginning. Do not mention any alternative or old tool name anywhere.

1. Project goal
   ============================================================

`bait2contig` is a lightweight command-line tool for finding contigs corresponding to bait/reference sequences under user-defined identity and bait-coverage thresholds.

Typical use cases include using full-length 16S rRNA sequences, ITS sequences, marker genes, MAG markers, viral markers, or custom reference sequences to locate candidate contigs from a contig FASTA file.

The tool has two main steps:

1. `bait2contig search`

   * Map bait/reference sequences to contigs.
   * Filter alignments by identity, bait coverage, and alignment length.
   * Output bait-contig hit-level TSV.
   * Optionally extract matched contigs as FASTA.

2. `bait2contig summarize`

   * Read the hit-level TSV generated by `search`.
   * Summarize contigs anchored by each bait.
   * Output bait-level summary TSV.

The mapping backend should be `minimap2`. The tool should parse minimap2 PAF output.

bait2contig search 
--contigs contigs.fa

6. minimap2 behavior
====================

The internal minimap2 command should be:

minimap2 -x {preset} -t {threads} {contigs} {bait} > {tmp_paf}

The order is important:

target/reference = contigs
query = bait

This ensures that in the PAF file:

query_id  = bait_id
target_id = ctg_id

Do not reverse the order.

Check whether minimap2 exists before running. If not found, exit with a clear error:

ERROR: minimap2 was not found. Please install minimap2 or provide its path with --minimap2.

minimap2 can read gzip-compressed FASTA input, so `.fa.gz` or `.fasta.gz` inputs can be passed directly to minimap2.

PAF handling:

1. minimap2 should write to a temporary plain-text PAF file.
2. Python should parse the temporary PAF file.
3. If --keep-paf:

   * without --gzip: move temporary PAF to final .paf
   * with --gzip: compress temporary PAF to final .paf.gz
4. If not --keep-paf:

   * delete temporary PAF after parsing

7. PAF parsing
==============

PAF first 12 columns:

0 query_id
1 query_len
2 query_start
3 query_end
4 strand
5 target_id
6 target_len
7 target_start
8 target_end
9 residue_matches
10 alignment_block_length
11 mapping_quality

In bait2contig:

bait_id = query_id
bait_len = query_len
ctg_id = target_id
ctg_len = target_len

Calculate:

identity = residue_matches / alignment_block_length
cov_bait = (query_end - query_start) / query_len
aln_length = alignment_block_length

Filter hits using:

identity >= --identity
cov_bait >= --coverage
aln_length >= --min-aln-length

Output identity and cov_bait with 6 decimal places.

If --best-only is used, keep only one best contig for each bait.

Best hit ranking:

1. identity descending
2. cov_bait descending
3. aln_length descending
4. ctg_len descending

9. Input file formats

---

## 9.1 contigs FASTA

Plain or gzip FASTA should be supported:

contigs.fa
contigs.fasta
contigs.fa.gz
contigs.fasta.gz

Example:

> contig_001 len=15320 circular=true
> ATGC...
> contig_002 len=8401
> ATGC...

The contig ID is the first token before whitespace.

For:

> contig_001 len=15320 circular=true

ctg_id should be:

contig_001

The tool should read contig lengths from the actual sequence length, not rely only on header length fields.

By default, search should not load all contig sequences into Python memory before minimap2. It should use a plain-text FASTA index for contig metadata and plain-FASTA sequence offsets.

Index path default:

<contigs>.bait2contig.fai

The index should be considered current only when these values match the source FASTA:

* index schema version
* absolute source path
* source file size
* source file mtime in nanoseconds

The index should not store full sequences. For plain FASTA, index building should use a mmap-based chunk scanner and may use multiple threads. Sequence extraction should seek to indexed offsets and read only requested contigs. For gzip FASTA, metadata can be indexed, but index building is sequential and sequence extraction may fall back to stream-based subset reading because gzip is not efficiently seekable.

10. is_circular logic
=====================

The `is_circular` column should be determined as follows:

1. If --circular-list is provided, contigs listed there are marked as True.
2. Otherwise, infer circularity from the contig FASTA header.
3. Otherwise, default to False.

Header circular keywords should be case-insensitive.

Recognize at least:

circular=true
is_circular=true
circular
circ=true

Example:

> contig_001 len=15320 circular=true

is_circular=True

Important:
`is_circular` is not de novo circularity detection. It is inferred only from FASTA headers or an optional circular contig list.

11. Contig extraction
=====================

Contig extraction should happen only when --extract-contigs is provided.

Example:

bait2contig search 
--contigs contigs.fa 
--bait bait.fa 
--out bait2contig.hits.tsv 
--extract-contigs matched_contigs.fa

This writes:

bait2contig.hits.tsv
matched_contigs.fa
bait2contig.hits.tsv.log

Default extraction thresholds:

extract_min_identity = --identity
extract_min_coverage = --coverage
extract_min_aln_length = --min-aln-length

The user may use stricter extraction thresholds than hit-table thresholds:

bait2contig search 
--contigs contigs.fa 
--bait bait.fa 
--out bait2contig.hits.tsv 
--identity 0.95 
--coverage 0.70 
--extract-contigs high_confidence_contigs.fa 
--extract-min-identity 0.99 
--extract-min-coverage 0.90

In this case:

* hits TSV uses 0.95 / 0.70
* extracted FASTA uses 0.99 / 0.90

---

## 11.1 --extract-mode

--extract-mode all

Extract all contigs passing extraction thresholds.

--extract-mode best

Extract the best contig for each bait.

Best hit ranking:

1. identity descending
2. cov_bait descending
3. aln_length descending
4. ctg_len descending

If multiple bait sequences point to the same best contig and deduplication is enabled, output the contig only once.

--extract-mode circular

Extract only contigs with is_circular=True.

--extract-mode non-circular

Extract only contigs with is_circular=False.

---

## 11.2 --extract-dedup and --no-extract-dedup

Deduplication should be enabled by default.

Default behavior:

--extract-dedup = True

If deduplication is enabled, the same ctg_id should be written only once even if matched by multiple bait sequences.

If the user specifies:

--no-extract-dedup

then the same contig may be written multiple times.

If --no-extract-dedup is used without --extract-rename, print a warning:

[WARN]    Duplicate FASTA IDs may be written because --no-extract-dedup was used without --extract-rename.

---

## 11.3 --extract-rename

If --extract-rename is not used, keep the original contig FASTA header.

Example:

> contig_001 len=15320 circular=true

If --extract-rename is used, use this header format:

> {ctg_id}|bait={bait_id}|identity={identity:.6f}|cov_bait={cov_bait:.6f}|aln_length={aln_length}|ctg_len={ctg_len}|circular={is_circular}

Example:

> contig_001|bait=Pace_16S_001|identity=0.991234|cov_bait=0.982394|aln_length=1450|ctg_len=32781|circular=False

Do not include lineage in FASTA headers by default.

---

## 11.4 --extract-include-lineage

If --extract-include-lineage is used together with --extract-rename, append lineage to the renamed FASTA header:

|lineage=d__Archaea;p__...

If --extract-include-lineage is used without --extract-rename, raise an error:

ERROR: --extract-include-lineage requires --extract-rename.

============================================================
16. Resume logic
================

When --resume is used:

1. Check whether the log file exists.
2. Check whether the output file exists and is non-empty.
3. Parse the last standardized marker block from the log.
4. Find the latest [BAIT2CONTIG_DONE] block matching the current command.
5. Confirm:

   * command matches the current subcommand
   * status=success
   * exit_code=0
   * output path matches the current actual output
   * output_size > 0
   * key parameters match
6. If all checks pass, skip the run and log:

[INFO]    Resume enabled: previous successful run found in log.
[INFO]    Output verified: bait2contig.hits.tsv.gz
[INFO]    Skipping search.

7. If checks fail, do not skip. Log the reason:

[WARN]    Resume log found but parameters changed: identity 0.97 -> 0.99
[INFO]    Re-running search.

8. If the log contains START but no DONE, treat it as incomplete and do not skip.
9. If the latest relevant marker is FAILED, do not skip.
10. If the log is malformed, do not crash; print a warning and rerun.

============================================================
17. Output existing behavior
============================

If output file already exists:

1. With --resume:

   * Check the log.
   * If previous run was successful and parameters match, skip.
   * Otherwise rerun.

2. With --rerun:

   * Force recomputation and overwrite output.

3. With --force:

   * Allow overwriting output.

4. Without --resume, --rerun, or --force:

   * Exit with error:

ERROR: output already exists: bait2contig.hits.tsv
Use --resume to reuse a completed run, --rerun to recompute, or --force to overwrite.

--resume and --rerun cannot be used together.

============================================================
18. Runtime resource monitoring
===============================

Record runtime, CPU usage, and memory usage.

Requirements:

1. Prefer psutil for detailed CPU and memory monitoring.
2. If psutil is not installed, do not fail.
3. Fall back to standard-library `resource` and Linux `/proc` child CPU sampling when available.
4. Try to include minimap2 child process resource usage.
5. Every --monitor-interval seconds, sample resource usage for final summary statistics.
6. Only when --verbose is set, write timestamped periodic resource lines to the log.
7. Resource monitoring failure must not fail the main program.

Verbose resource log example:

[RESOURCE] elapsed=30.0s rss_mb=842.5 cpu_percent=1250.4
[RESOURCE] elapsed=60.0s rss_mb=1189.3 cpu_percent=1732.8
[RESOURCE] elapsed=90.0s rss_mb=1234.6 cpu_percent=1650.2

Final DONE or FAILED marker should include:

peak_rss_mb=1234.56
mean_cpu_percent=632.4
max_cpu_percent=2180.1

Notes:

* cpu_percent can exceed 100 because minimap2 is multithreaded.
* If cpu_percent cannot be measured, write NA.
* If peak_rss_mb cannot be measured, write NA.
